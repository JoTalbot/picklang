# Контракт восстановления и проверки

## Идентичность исполнения

`execution_id` обозначает одно исполнение с неизменными входами. При повторном
`run()` изменение входов, имени workflow или `workflow_version` возвращает
`FAILED` без запуска обработчиков и без изменения журнала исполнения.

Для Python-workflow передавайте стабильную версию явно:

```python
executor.run("order-42", workflow, inputs, workflow_version="payments-v2")
```

Автоматического надёжного определения версии произвольного Python-кода нет.
При неизменной версии вызывающая сторона отвечает за детерминированный порядок
шагов. Обёртка `run_pick()` автоматически использует SHA-256 исходного текста:
даже изменение форматирования требует нового исполнения или явной миграции.

Каждый сохранённый результат содержит digest входа активности. Изменённый
payload при replay отклоняется. Параллельные группы используют общую с
последовательными шагами нумерацию позиций, а внутри группы — индекс ветви.

## Совместимость журналов

- Снимки теперь содержат сигналы и идентичность исполнения; они сохраняются при
  компакции. Для старых некомпактированных снимков читается префикс журнала.
- Для старого компактированного снимка сигналы и идентичность восстанавливаются
  из таблицы archive. Если архив был удалён извне, требуется ручная миграция.
- Старые идентификаторы параллельных шагов `par0:...` неоднозначны. Replay таких
  исполнений отклоняется с требованием явной миграции, а не повторяет эффекты.
- Старые PICK-исполнения без версии исходника не принимают новую привязку версии
  автоматически. Не меняйте идентичность исполнения молча.

## Идемпотентность внешних операций

`idempotent()` кеширует в том числе `None`. Это локальный кеш результата,
не транзакция с банком: сбой после внешней операции, но до записи кеша всё ещё
может привести к повтору. Дедупликация должна поддерживаться внешним сервисом
по стабильному ключу исполнения и шага. Обёртка также не заменяет распределённую
блокировку конкурентных вызовов. SQLite-соединение обёртки не предназначено
для совместного использования из разных потоков.

Локальный executor блокирует одно исполнение через POSIX `flock`; на Windows
эта блокировка отсутствует. Не запускайте там конкурентные resume.

## CAS и долговечность

CAS публикует объект атомарно из уникального временного файла; конкурентные
писатели одного digest не используют общий `.tmp`. Содержимое файла сбрасывается
через `fsync`, но это не гарантия сохранности всего исполнения при потере питания:
SQLite работает в WAL с `synchronous=NORMAL`, а fsync каталога CAS не выполняется.
Хэши выявляют изменение байтов, но не подтверждают правильность внешнего действия.

## Проверки

```bash
pip install -e '.[dev]'
python -m pytest tests/ -q -m 'not temporal'
python -m pytest tests/ -q -m temporal
python -m build
```

Temporal-тесты выделены маркером и отдельным заданием CI. Если SDK отсутствует,
они пропускаются; при установленном SDK ошибки сервера и workflow — ошибки теста.
Токеновые тесты требуют словаря `cl100k_base` в кеше tiktoken либо сетевого доступа
к его источнику. Не заменяйте реальные токеновые измерения оценкой по символам.
Live-оценки расходуют API-квоту и не относятся к локальным unit-тестам.

Для сравнения PICK и Python измеряйте не только исходники, но и одинаковые
модели, задачи, инструменты, число повторов, долю успехов, полный расход токенов,
стоимость и задержку. См. `PAIRED_AB.md` и `PAIRED_RUNNER.md`.
