# localStorage и JSON — как игра помнит тебя

Без этого файла игра начиналась бы заново после каждого случайного свайпа.
Разберём два слова.

---

## localStorage — записная книжка браузера

**Что это:** маленькое хранилище, встроенное в каждый браузер.
Уже есть у всех, ставить ничего не надо. Умеет хранить **только текст**
и только парами «имя → значение».

**Аналогия:** стикер на холодильнике. Выключили свет, перезагрузили
страницу — стикер на месте.

Всего две команды:

```js
localStorage.setItem("ключ", "значение");  // записать
localStorage.getItem("ключ");              // прочитать (или null, если нет)
localStorage.removeItem("ключ");           // стереть
```

**Ограничение:** примерно 5 мегабайт на сайт. Наша игра весит
несколько килобайт — мебель в грузовике.

---

## Проблема: localStorage не умеет хранить объекты

Вот наша память игры:

```js
{ scene: "corridor", items: ["Ключ-карта"], suit: 4 }
```

Это объект. Записать его напрямую нельзя — ячейка принимает только текст.

---

## JSON — способ превратить объект в текст и обратно

**Что это:** формат записи данных текстом. Выглядит почти как код,
но это именно текст — его можно сохранить, отправить, распечатать.

```js
JSON.stringify({ scene: "corridor" })  // → '{"scene":"corridor"}'
JSON.parse('{"scene":"corridor"}')     // → { scene: "corridor" }
```

**Аналогия:** разобрать шкаф на детали, подписать каждую и сложить в коробку
(`stringify`). Потом достать и собрать обратно (`parse`).

---

## Как это работает в игре

Из `src/state.js`, максимально коротко:

```js
const Save = {
  write(state) {
    localStorage.setItem("orbita9.save.v1", JSON.stringify(state));
  },
  read() {
    const raw = localStorage.getItem("orbita9.save.v1");
    if (!raw) return null;          // сохранения нет
    return JSON.parse(raw);          // собрали мебель обратно
  }
};
```

И вызывается после каждого выбора игрока, в `src/game.js`:

```js
Save.write(state);
goto(choice.next);
```

**Порядок важен:** сначала сохранили, потом ушли. Если бы наоборот —
при закрытии вкладки в момент перехода последний выбор мог бы потеряться.

---

## Почему в коде ещё куча проверок

В настоящем `Save.read()` есть такие строки:

```js
if (!data.skills || !Array.isArray(data.items)) return null;
```

Это **защита от битого сохранения**. Причины бывают разные: игрок
почистил данные сайта, браузер обновился, ты сама поменяла формат данных.
Без проверки игра упала бы с белым экраном. С проверкой — просто начнётся заново.

Правило на всю жизнь: **данные извне никогда не доверяй**, даже если
это данные, которые ты сама только что записала.

---

## Что будет, если почистить данные сайта

Сохранение исчезнет. Это не баг — это и есть суть localStorage:
он живёт только в этом браузере на этом устройстве.

Именно поэтому в `DECISIONS.md` записано, что облачные сохранения
мы не делаем: для этого нужен сервер, деньги и аккаунты.
