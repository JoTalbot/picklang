# PICK — язык, спроектированный под автора-LLM

## Откуда берётся расход токенов у LLM — и что с этим делает PICK

LLM платит токенами не за «смысл», а за всё, что вынуждена печатать:

| Статья расхода | Как выглядит в Python/JSON | Что делает PICK |
|---|---|---|
| Бойлерплейт | импорты, классы, `def`, `try/except`, сериализация, объявления типов | Прелюдия среды подразумевается. Программа начинается сразу со смысла: `> order(id, amt)` |
| Механика надёжности | Ручная сага: список компенсаций, обратный проход, подсчёт откатов — в каждом проекте заново | `x = call ! undo` — одна строка. Механика (LIFO, идемпотентность) живёт в рантайме, а не в тексте от LLM |
| Ожидание/стражи | Циклы polling, проверки None, raise с текстами | `@wait approval`, `? cond -> fail "..."` — по одной строке |
| Повтор контекста при итерациях | На каждое изменение модель пересылает файл целиком | Diff-режим: `@base <digest>` + патч `~N:`/`+N:`/`-N`. Измерено: 45 токенов вместо 350 (Python целиком) — см. `bench_tokens.py` |
| Неоднозначность | Синонимы, идиомы, «как принято в этом проекте» → модель дообъясняет и ошибается | Одна конструкция на смысл, построчная грамматика, структурированные ошибки `line N: ожидается ...` — чинится одним маленьким патчем |
| Повторяющиеся куски | Копипаст типовых блоков | Блоки адресуются в CAS по хэшу; словарь проекта (vocabulary) даёт короткие имена дорогому контексту |

Замеры на примерах из `examples/` (tiktoken, cl100k_base): сага оплаты — 121 токен
против 350 у эквивалентного Python и 305 у JSON-воркфлоу (2.5–2.9x); агент с
human-in-the-loop — 111 против 229 (2.1x); итерационный патч — ещё 2.7x сверху.

Честная граница: PICK не делает короче *уникальную* логику. Если шаг — нетривиальный
алгоритм, он живёт в функции хоста на обычном языке, а PICK лишь вызывает её по имени.
PICK сжимает оркестрацию, надёжность и итерации — то, чем LLM занята большую часть
времени в реальной разработке.

## Грамматика v0.1 (вся)

```
# комментарий
> name(a, b)                 цель: имя программы и её входы
x = mod.fn(a, 1, "s")        вызов хост-функции, результат в x
x = mod.fn(a) ! mod.undo(x)  шаг саги: компенсация при позднейшем сбое (LIFO)
? x.ok -> fail "причина"     страж
@wait approval               durable-пауза до внешнего сигнала; значение -> в approval
a >> b.f(3) >> c.g()         пайплайн: результат слева — первый аргумент справа
out {k: x, t: y.tx}          результат программы
```

Выражения: вызовы, переменные, доступ к полям `p.tx`, литералы (числа, строки,
списки), карты `{k: expr}`. Одна строка — один шаг. Никаких блоков и отступов.

## Ошибки как интерфейс для LLM

Парсер не говорит «SyntaxError где-то». Он говорит, на какой строке и что именно
ожидалось (`line 4: страж записывается как: ? условие -> fail "..."`). Для модели
это разница между «перепиши всё» (~все токены) и «почини строку 4» (~10 токенов).
Тот же принцип — в diff-режиме: патч к несовпавшему digest базы запрещён, модель
не может молча изменить программу, которую не видела.

## Расширения первой волны

- **Словарь проекта**: `&alias(a, b)` разворачивается в блок из CAS-словаря
  (`picklang/vocab.py`); тело блока хранится один раз по digest.
- **Minify**: `compress()` переименовывает переменные в `a, b, c...` и отдаёт
  source-map; `expand()` восстанавливает читаемые имена. Функции хоста и строки
  не переименовываются.
- **Genesis**: `generate(intent_dict)` собирает программу из намерения — модель
  платит только за шаги, компенсации и стражей, а не за синтаксис.
- **Исправление ошибок**: `suggest_patches()` возвращает готовые `~N:`-патчи,
  `fix_source()` применяет их. Статический контроль — `check_source()` до запуска.

## Агентные конструкции второй волны

```
!budget steps<20, tokens<4000     рантайм следит за расходом и останавливает цикл
a = research(q) || b = prices(q)  параллельные ветви, слияние по порядку
done when: sent.id, ok == True    критерии готовности, проверяемые до результата
found >> top(3) >> fields("t")    проекции stdlib: режут результат до контекста
bank.charge("secret:BANK_KEY", 5) секрет подставит рантайм из окружения
```
