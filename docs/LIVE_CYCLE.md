# Живой цикл задачи «подписка»: методика измерения

Этот отчёт формируется командой `python bench_live_cycle.py --write`.

## Что измеряем

Сравниваются токены текста, который должен подготовить агент для задачи и исправления. В PICK учитывается сериализованное содержимое словаря проекта, созданное один раз, намерение на каждую задачу и текст патча. В классическом сценарии учитываются полный Python-файл и его полная пересылка при исправлении.

Суммарная модель затрат для N задач:

- **PICK:** `токены словаря + N × (намерение + патч)`
- **Python:** `N × (полный исходный код + повторная отправка кода)`

Отчёт выводит общую и среднюю стоимость для 1, 10 и 100 задач, а также точку окупаемости словаря. Для воспроизводимости используется `cl100k_base` при установленном `tiktoken`; без него оценка по символам/4 приблизительна и не должна использоваться для заявления о точном выигрыше.

## Важные ограничения

Предыдущая версия отчёта показывала выигрыш 4.1x, но не включала первоначальную стоимость словаря PICK. Поэтому этот коэффициент **не является подтверждённым результатом** и не должен использоваться как доказательство превосходства.

Даже после учёта словаря это пока сравнение токенов генерации, а не полный end-to-end бенчмарк. Оно не включает системные промпты, полную историю, ответы модели, API-телеметрию входных/выходных токенов, стоимость инструментов, повторные попытки, время выполнения или ручное вмешательство. Также не доказана полная семантическая эквивалентность двух реализаций.

Для заявления «дешевле, быстрее и надёжнее» нужны отдельные измерения на одинаковых задачах: реальные затраты API, wall-clock время, доля успешных результатов, количество исправлений и регрессионные тесты. Durable-проверка ниже подтверждает лишь тестовый сценарий восстановления после искусственного сбоя, а не общее превосходство инструмента.
