# Архитектура: язык для LLM + durable-исполнитель + CAS-доказуемость

```
LLM ──PICK (мало токенов)──► parser ──► Canonical IR (JSON) ──► CAS (digest программы)
                                   │
                                   ▼
                        DurableExecutor (идея Temporal):
                        workflow переигрывается от начала, завершённые
                        активности берутся из журнала, а не выполняются
                                   │
              каждый результат ──► CAS (идея WEAVE/Prolepsis) + событие
                                   в hash-цепочку журнала
                                   ▼
              verify: цепочка цела? артефакты совпадают с хэшами? -> digest
```

Слои и их честные границы:

- **picklang/** — синтаксис, IR, интерпретатор, diff-патчи. Не знает про хранение.
- **durable_weave/cas.py** — контентно-адресное хранилище SHA-256: дедупликация,
  атомарная публикация, verify пересчётом хэша. После аварийного завершения
  `recover_temporary_files(min_age=300)` удаляет только старые `.cas-*.tmp`;
  свежие файлы активных писателей, symlink и опубликованные объекты не трогает.
- **durable_weave/sqlite_backend.py** — append-only журнал с хэш-цепочкой; digest
  исполнения = хэш последнего события.
- **durable_weave/executor.py** — replay-исполнитель: коммит активности =
  CAS + событие; только после этого следующий шаг. Падение между шагами
  переживается; падение *внутри* внешней системы — нет: exactly-once внешних
  эффектов не существует, обработчики обязаны быть идемпотентны по ключу.
- **durable_weave/pickrun.py** — связка: вызов PICK = активность исполнителя;
  `@wait` = durable-пауза (WAITING), сигнал подаётся отдельной операцией.

Что сознательно НЕ заявляется: распределённый консенсус, multi-host исполнение,
exactly-once сайд-эффектов, надёжность на произвольных промптах. Это v0.1 —
минимальное ядро, где каждая заявленная гарантия покрыта тестом.
