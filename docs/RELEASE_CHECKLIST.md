# Релизный контрольный список

Этот список отделяет локально воспроизводимые проверки от live-проверок, зависящих от доступности OpenRouter и квот бесплатных моделей.

## Автоматически проверяется в GitHub Actions

- [ ] Репозиторий и SHA запуска совпадают с актуальным `main`.
- [ ] Все тесты из `tests/` проходят, включая регрессию общего HTTP-дедлайна.
- [ ] Собираются wheel и source distribution.
- [ ] CLI запускается, демонстрационный сценарий завершается.
- [ ] Live-каскад выполняет шесть задач; сводка публикуется в логах и Job Summary без загрузки артефактов. Эта проверка запускается вручную через workflow_dispatch с включённым run_live, чтобы обычные push не расходовали квоту OpenRouter.

## Проверки перед публикацией релиза

1. Проверить версию в `pyproject.toml`, заметках релиза и Git-теге.
2. Установить wheel в чистое виртуальное окружение и проверить `pick --help` и демонстрацию.
3. Проверить содержимое wheel и sdist: пакетные модули, README и лицензионные метаданные.
4. Выполнить полный набор тестов повторно на точном коммите, который будет отмечен тегом.
5. При доступной квоте вручную запустить workflow_dispatch с run_live=true, затем проверить live-результаты и ошибки API. Пропущенный live job не считается успешной live-проверкой; успешный прогон не гарантирует доступность бесплатных моделей в будущем.
6. Создавать тег и GitHub Release только после успешных обязательных проверок; не перезаписывать уже опубликованный тег.

## Интерпретация live-метрик

Результаты OpenRouter — снимок конкретного запуска. Модель, число попыток, задержка и расход токенов могут меняться между запусками. Исторические таблицы в документации нельзя считать результатом текущего запуска; текущие значения находятся в логах и Job Summary соответствующего workflow run.
