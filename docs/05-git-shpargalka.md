# Git — шпаргалка на 5 команд

Git пугает не сложностью, а количеством слов. На самом деле для проекта
хватает пяти команд. Остальное — потом.

---

## Главная идея

**Коммит** — это снимок проекта в конкретный момент с подписью «что изменилось».
Как сохранение в игре, только для кода.

Зачем: через две недели ты не вспомнишь, что меняла. А с коммитами
можно посмотреть историю и откатиться к любому моменту.

---

## Пять команд

### 1. Посмотреть, что изменилось

```bash
git status
```

Показывает: какие файлы изменены, какие новые, что готово к сохранению.
**Это команда, которую ты будешь вводить чаще всех.** Она бесплатная, ничего не ломает.

### 2. Подготовить изменения

```bash
git add .
```

Точка значит «всё в этой папке». Файлы попадают в «корзину для отправки».

### 3. Сделать сохранение

```bash
git commit -m "Шаг 3: добавил хранение записок"
```

Сообщение пиши человеческим языком и в настоящем времени, как в CHANGELOG.
Плохо: `fix`, `update`, `123`. Хорошо: «Шаг 5: добавил проверки навыков».

### 4. Отправить на GitHub

```bash
git push
```

Локальные сохранения уезжают в облако, в твой репозиторий.

### 5. Посмотреть историю

```bash
git log --oneline
```

Список всех коммитов, по одной строке. Выход — клавиша `q`.

---

## Три правила, которые спасут тебе вечер

1. **Коммить часто.** Один шаг — один коммит. Лучше пять маленьких,
   чем один на 800 строк, в котором непонятно что.
2. **Не коммить секреты.** Ключи, пароли, токены — только в `.env`,
   а `.env` — в `.gitignore`. Если секрет попал в коммит, он остаётся
   в истории навсегда, даже если ты удалишь файл.
3. **`git status` перед каждым коммитом.** Пять секунд, которые ловят
   случайно добавленную папку `node_modules` на 300 мегабайт.

---

## Что такое `.gitignore`

Файл-список «что НЕ отслеживать». Туда попадает то, что не является
частью проекта:

- `node_modules/` — чужие библиотеки, скачиваются заново одной командой
- `.env` — твои секреты
- `.DS_Store`, `Thumbs.db` — мусор операционной системы
- `*.log` — журналы работы

У нас такой файл уже есть, в корне проекта.

---

## Если что-то пошло не так

```bash
git diff              # что именно изменилось, построчно
git restore файл.js   # отменить изменения в одном файле (до коммита)
git log --oneline     # где я вообще
```

⚠️ Не запускай `git reset --hard` и `git push --force`, пока не понимаешь,
что они делают: они стирают работу без возможности вернуть.
Если сомневаешься — спроси, а не надейся.

---

## А GitHub — это что?

Git — программа у тебя на компьютере, она хранит историю.
GitHub — сайт, где копия этой истории лежит в интернете.

**Зачем:** чтобы проект не жил только на одном устройстве, и чтобы
его можно было показать по ссылке.
