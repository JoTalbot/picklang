# PICK + durable-weave

**Компактный язык программ для LLM-агентов и durable-рантайм с проверяемым исполнением.**

Экономия зависит от задачи, повторного использования словаря, контекста и исправлений. Приведённые ниже цифры относятся к конкретным тестовым корпусам и не гарантируют общего выигрыша по стоимости или времени.

Идея проекта: главная статья расхода при работе с LLM — не «умные» строки, а
бойлерплейт, ручная механика надёжности и пересылка всего файла на каждое
изменение. PICK убирает все три: компактный построчный синтаксис для оркестрации,
саги и ожиданий одной строкой, diff-патчи по digest вместо целых программ.
Локальный durable-слой переживает сбои между шагами, а каждый результат складывается
в CAS с SHA-256 (дедупликация, tamper-evidence, verify). Temporal доступен как
опциональный backend для долгих и распределённых workflow; для обычной разработки
и тестов отдельный Temporal Service не требуется.

## Быстрый старт

```bash
pip install pytest tiktoken   # tiktoken — только для бенчмарка токенов
python3 bench_tokens.py       # сколько токенов экономит PICK: цифры, а не лозунги
python3 examples/run_demo.py  # сага оплаты: успех, откат; агент с одобрением человека
python3 -m pytest tests/ -q   # полный набор unit/regression-тестов
```

## Пример компактной программы

В одном из примеров PICK занимает 121 токен, а выбранный эквивалент Python — 350. Это локальное сравнение исходников, а не полный end-to-end расход агента: системные промпты, контекст, ответы модели, исправления и настройка словаря могут изменить итог.

```pick
> order(id, amt)
r = stock.reserve(id) ! stock.release(id)
p = bank.charge(id, amt) ! bank.refund(p.tx)
? p.ok -> fail "банк отклонил платёж"
s = post.book(id) ! post.cancel(s.track)
mail.send(id, s.track)
out {order: id, tx: p.tx, track: s.track}
```

Эквивалент на Python — в `examples/payment.py`, на JSON-воркфлоу — в
`examples/payment.json`. Полная грамматика (она маленькая) — `docs/LANGUAGE.md`.

## Что внутри (реализовано)

1. **Словарь проекта в CAS** (`picklang/vocab.py`) — типовые блоки один раз кладутся
   в CAS по digest, дальше LLM пишет `&pay(id, amt)` вместо всего блока.
2. **Ошибки готовым патчем** (`picklang/fix.py`) — вместо текста ошибки модель
   получает применимый diff `~N: ...` и чинит программу одной операцией.
3. **Статический контроль IR** (`picklang/check.py`) — неизвестные функции, арность,
   переменные до привязки ловятся до запуска, без дорогого цикла «запуск→падение».
4. **Генератор из намерения** (`picklang/genesis.py`) — LLM перечисляет только
   уникальное (шаги/компенсации/стражи dict-ом), механику в PICK достраивает генератор.
5. **Сжатие идентификаторов** (`picklang/minify.py`) — переменные → `a, b, c` с
   source-map для обратной развёртки человеку; на длинных именах даёт ещё экономию.
6. **Публичный корпус бенчмарков** (`bench/corpus/`, 8 задач, `bench_corpus.py`):
   суммарно 609 токенов PICK против 942 у Python (1,55× в этом конкретном корпусе). Это сравнение исходников, а не полного агентного цикла; эквивалентность и стоимость полного цикла требуют отдельной проверки. Методика и ограничения — в `docs/BENCHMARKS.md` и `docs/LIVE_CYCLE.md`.
7. **Опциональный Temporal-адаптер и MCP** (`durable_weave/temporal_adapter.py`, `picklang/mcp.py`):
   тот же IR можно исполнять на Temporal при установленном SDK и доступном сервисе;
   обычный локальный путь от Temporal не зависит. Любой MCP-сервер становится библиотекой
   функций PICK (демо: `examples/mcp_server.py`).

## Как это работает

- `picklang/` — язык: парсер → Canonical IR (JSON) → интерпретатор; diff-режим
  (`@base <digest>`, `~N:`, `+N:`, `-N`) для итераций за десятки токенов.
- `durable_weave/` — рантайм: CAS-хранилище, журнал событий с хэш-цепочкой,
  replay-исполнитель, саги, durable-сигналы (`@wait`), верификация исполнения.
- Связка `durable_weave/pickrun.py`: каждый вызов PICK — активность; падение
  процесса между шагами не повторяет уже оплаченные внешним системам шаги.

## Вторая волна: для LLM-агентов

Главный расход агента — не код, а результаты инструментов и болтовня вокруг.
Поэтому:

- **Проекции и лимиты** (`picklang/stdlib.py`, `picklang/result_guard.py`):
  `found >> top(3) >> fields("title", "url")` режет ответ рантаймом до контекста;
  синтетический замер `bench_agent_tools.py` показывает сокращение объёма тестового ответа после проекций. Он не является измерением стоимости полного агентного цикла. Что не влезло в лимит — уезжает в CAS по `ref`, а не в контекст.
- **Бюджеты**: `!budget steps<20, tokens<4000` — рантайм сам останавливает цикл.
- **Компактный статус** (`picklang/status.py`): `ok 3 bank.charge d=8f3a…` — одна
  строка на шаг вместо логов, восстанавливается и из журнала исполнителя.
- **Task cards**: `done when: sent.id, approval == True` — критерии готовности
  проверяются рантаймом, агент не объявит победу раньше времени.
- **Контекст слотами** (`durable_weave/slots.py`): состояние в CAS по именам,
  субагенту — срез `slice([...])`, между агентами — `diff` снимков, а не вся история.
- **Безопасность**: capabilities на программу, `secret:NAME` подставляет рантайм
  из окружения (в контекст не попадает), ответы недоверенных инструментов
  помечаются `{"data": ..., "untrusted": True}` — данные, а не инструкции.
- **Параллельные ветви**: `a = research(q) || b = prices(q)` — субагентные ветки
  одним символом, слияние результатов по порядку объявления.

## Распределённое исполнение (опциональный backend)

Temporal нужен для долгих workflow, внешних сигналов и исполнения на отдельных
воркерах. Локальный durable-исполнитель остаётся стандартным путём для разработки
и тестов. Интеграционные проверки Temporal запускаются отдельно в CI и должны
считаться пройденными только при явном `PASS`; ошибки старта сервера, воркера
и workflow не маскируются как пропуск.

## Живой A/B каскадов

Live evaluation in GitHub Actions uses the `GROQ_TOKEN` repository secret with Groq's OpenAI-compatible API.
The default fallback tiers are `openai/gpt-oss-20b` then `openai/gpt-oss-120b`. Groq usage depends on the
account's rate limits and billing; the workflow stops attempting remaining tasks after the first provider 429.
To override model tiers, configure repository variable `PICK_LIVE_MODEL_TIERS` as JSON arrays of model IDs
ordered by fallback tier, for example `[["openai/gpt-oss-20b"],["openai/gpt-oss-120b"]]`.

Sequential против hedged на 3 задачах (`docs/LIVE_HEDGE.md`): оба 3/3,
hedged 42 с суммарно против 50 с и 5556 токенов против 6294. На шумном
free tier это тенденция: hedged страхует от хвоста задержек (в прошлом
прогоне одна задача висела 423 с), а не ускоряет медиану гарантированно.

## Закалка и кластерный краш-тест

- Property-паритет AOT<->интерпретатор на 300 случайных программах; фаззинг парсера
  нашёл и закрыл RecursionError на глубокой вложенности (лимит глубины 40).
- Журнал под нагрузкой (`docs/LOAD.md`): 100k событий — запись 97k соб/с, полный
  verify 0.4 с, выборочный 15 мс, resume после компакции 6 мс.
- Temporal: воркер, убитый во время `@wait`, заменён новым процессом — workflow
  завершился на нём (`tools/temporal_restart.py`, PASS). Находка: time-skipping
  окружение в этом сценарии зависает, локальный dev-сервер — нет.
- Сводная живая статистика (`docs/LIVE_STATS.md`): медиана решённой задачи 17.2 с
  и 2363 токена; накопление раундов упёрлось в дневную квоту free tier (50/день).

Пакет оформлен: `pyproject.toml` (`pip install -e .`), консольная команда `pick`,

## Девятая волна: ещё скорость

- **AOT на локальных переменных**: переменные программы — настоящие локалы Python,
  env собирается обратным проходом перед return; словарь остался только на входе/выходе.
- **Hedged-каскад**: сильная модель стартует параллельно через hedge-delay, а не
  после полного провала дешёвой; побеждает первый валидный ответ.
- **Меньше записей**: digest входа считается хэшем прямо в событии, без CAS-объекта.
- **Пакетная генерация** (`picklang/batch_gen.py`): очередь задач — один вызов
  модели со списком программ, провалившиеся догенерируются по одному.

## Восьмая волна: упрощение и скорость по семи пунктам

- **Ленивые токены**: точный BPE-подсчёт — только при `!budget tokens` в программе,
  иначе оценка по символам. Интерпретатор на конкурентной задаче: 124 -> ~30 мкс.
- **Durable-тюнинг**: WAL + synchronous=NORMAL, frontier коммитится одной транзакцией.
- **Капы рассуждений в каскаде по умолчанию** (512/1024 токена вместо безлимита).
- **Один backend журнала**: JSONL удалён, остался SQLite; один общий коммит шага
  (`_commit_activity`) и одно ядро replay для sync и async исполнителей.
- **Аудит синтаксиса** (`tools/syntax_audit.py`): все 15 форм живут хотя бы в одном
  корпусе — удалять нечего, механизм аудита оставлен на будущее.

## Седьмая волна: глубокая производительность

- **AOT покрывает почти всё**: batch-циклы (`fn.batch` одним вызовом), `done when`
  с настоящим `TaskNotDone`, саги с компенсациями LIFO. Быстрым путём не берутся
  только бюджеты, wait-таймауты, taint и durable-хуки.
- **Конкурентный замер** (`bench_compare.py`, `docs/COMPARE.md`): на задаче
  «поиск -> top(2) -> формат» Pick AOT 4.9 мкс, интерпретатор 124 мкс,
  LangGraph без чекпоинтера 824 мкс, durable-исполнитель 693 мкс
  (единственный с журналом, хэш-цепочкой и CAS на каждый шаг).

## Шестая волна: ускорения

- **Снимки состояния** каждые N шагов: resume стартует со снимка completed-карты
  в CAS и доигрывает только хвост журнала, а не всё с начала.
- **AOT-компиляция** в Python-замыкания по digest программы; проекции
  `top >> fields` слиты в один проход. **Групповой коммит** SQLite и выборочный verify.
- **Async-исполнитель** на asyncio с тем же журналом и digest-гарантиями.
- **Префетч на ожидании**: read-only шаги после `@wait` выполняются, пока человек
  думает; пишущие — никогда. **Батч в циклах**: `for` с `fn.batch` — один вызов
  на всю коллекцию.
- **Каскад моделей**: маленькая сначала, большая только при провале валидации.
  **Промпт-кэш**: статичный префикс контекста стабилен между задачами
  (`prefix_digest`). **Стриминговый разбор** намерения ловит мусор до конца генерации.
- **TSV-укладка** табличных результатов вместо JSON (на 10 строках 271 -> 167 ток.),
  цена алиаса словаря в токенах при регистрации, замер one-shot против ReAct:
  8 задач — 8 генераций против ~51 вызова модели (6.4x).

## Пятая волна: агент улучшает сам себя

- **Автомайнинг словаря** (`traces_mine.py`): частые цепочки вызовов из трасс
  предлагаются блоками словаря с оценкой экономии. **Навыки** (`skills.py`):
  только верифицированные исполнения становятся переиспользуемыми активами в CAS.
  **Консолидация памяти** (`memory.py`): эпизоды -> уроки по инструментам.
- **Tool RAG + контекстный компилятор**: модель видит top-k релевантных
  инструментов; системный промпт собирается из карточки+контрактов по digest.
  **Дрейф контрактов**: diff схем и список программ, которых ломает изменение.
- **Статистика инструментов** планировщику (p50/падения), **песочница
  record/replay** для спекулятивных веток (в живую не ходит), **политика
  эскалации** риск × неуверенность с одной строкой человеку.
- **Статическое доказательство безопасности**: денежный/необратимый шаг без
  предшествующего `@wait approval` недостижим — теорема о графе, `proof.py`.
  **Соревновательный корпус**: инъекции/taint/бюджеты/подмены — 5/5 остановлено
  (`eval_adversarial.py`). **Атрибуция расхода** по шагам из журнала.

## Волна ускорений (замерено до/после)

- **Кэш скомпилированной программы + кодировки токенизатора**: прогрев обязателен,
  в установившемся режиме интерпретатор — ~8–10 мкс/запуск на шаг вместо холодных ~70 мкс.
- **Constrained decoding по умолчанию** в живом цикле (json_schema) с честным
  откатом без схемы, если провайдер её не умеет.
- **Лимит reasoning в роутере**: `reasoning_max_tokens` + учёт reasoning-токенов
  отдельно в суммарном usage всех попыток.
- **Pushdown-проекции**: MCP-инструмент `search(query, limit, fields)` режет на
  сервере — лишнее по сети не едет вообще.
- **Параллельный frontier durable-исполнителя**: активности выполняются
  одновременно, коммиты в журнал — в объявленном порядке (digest стабилен):
  2 шага по 200 мс — 0,21 с вместо 0,40 с.
- **Пул MCP-соединений и батчинг**: одно соединение на серию вызовов.
- **Живой eval моделей** (`live_eval_models.py`, `docs/LIVE_EVAL.md`): те же
  3 задачи намерения разным моделям; бесплатный тариф нестабилен, и это записано
  в результатах как есть (4–5 из 6 валидных от прогона к прогону).

## Четвёртая волна: корректность, генерация, продакшен (п.1–18 одним батчем)

- **Язык**: гигиена блоков словаря (внутренние переменные переименовываются,
  экспорт блока — последняя переменная), `@wait signal :24h else <шаг>`,
  ретраи `call ^3`, циклы `for x in xs: <шаг>`, эффекты `@fx money` со статическим
  предупреждением без компенсации.
- **Генерация**: JSON Schema намерения для constrained decoding (+GBNF),
  контракты функций с проверкой полей результатов (`charge.track` вместо `.tx`
  ловится до запуска), замкнутый авторемонт патчами с логом кругов.
- **Агенты**: taint-контроль (недоверенный `web.read` не уходит в оплату без
  одобрения), автокомпакт слотов (summary + ref в CAS), приблизительный
  семантический кэш (Жаккар по словам, включается явно), роутер моделей
  с фолбэком и суммарным usage всех попыток.
- **Рантайм**: SQLite-бэкенд журнала (та же хэш-цепочка, транзакционно),
  идемпотентные обработчики денег из коробки (SQLite-дедуп по ключу),
  **Temporal-адаптер прогнан против живого тестового сервера: PASS**
  (`tools/temporal_smoke.py`).
- **Инструменты**: CLI `pick run/check/fmt/bench/verify`, eval-корпус из 20 задач
  (`eval_harness.py`, успешность на моках 20/20 — нижняя планка, `docs/EVAL.md`),
  сам PICK как MCP-сервер (`examples/pick_mcp_server.py`: pick_check/pick_digest/pick_run).

## Третья волна: между агентами

- **Перенос контекста между процессами по digest** (`durable_weave/context_transport.py`):
  агент публикует bundle слотов (манифест по хэшам + CAS-объекты) в inbox, второй
  агент — отдельным процессом — забирает по одной строке handoff и проверяет
  каждый объект по хэшу до импорта. Замер `bench_agent_handoff.py`: контекст
  целиком 1 532 токена против 170 за handoff (digest + слоты + diff), сам бандл
  едет файлом мимо окна модели.
- **Семантический кэш подзадач** (`picklang/semcache.py`): одинаковое намерение
  (namespace + функция + digest аргументов) — готовый результат из CAS без вызова
  модели. Кэшируется только помеченное (`llm.*`, чтения); сайд-эффекты
  (`bank.charge`, `mail.send`) не кэшируются by design. Смена namespace (промптов)
  инвалидирует всё разом, есть TTL и `cached_run` для целых запусков.

## Живой цикл: замер на одной задаче

`bench_live_cycle.py` считает модель токенов для задачи «подписка», включая первоначальную стоимость словаря и повторную отправку кода в выбранном сценарии. Исторический коэффициент 4,1× исключён как неподтверждённый: текущий расчёт остаётся token-only и не доказывает эквивалентность, снижение реальной стоимости API или ускорение полного агентного цикла. Durable-тест отдельно проверяет восстановление после искусственного сбоя без повторного вызова списания.

## Честные границы v0.1

Нет распределённого исполнения и консенсуса; нет exactly-once внешних эффектов
(обработчики идемпотентны по ключу — как Activities в Temporal); бенчмарк токенов —
на двух примерах из репозитория, а не на индустриальном корпусе. Что делать
дальше — `docs/IDEAS.md` (12 пунктов, включая словарь проекта в CAS, Temporal-адаптер

Проект собран как развитие идей WEAVE/Prolepsis (CAS, event-log, доказуемость)
и Temporal (durable execution, саги, сигналы), перенесённых в задачу
«LLM как главный автор кода». Репозиторий очищен и перезапущен под эту задачу;
прежнее содержимое доступно в истории git до коммита очистки.
